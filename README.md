# 《极世界》ExtremeWorld MMORPG 游戏服务器项目

## 项目概述

ExtremeWorld 是一个基于 C#/.NET Framework 4.8 开发的 MMORPG（大型多人在线角色扮演游戏）服务器端项目。本项目实现了完整的游戏后端架构，包括用户管理、角色系统、地图管理、战斗系统、技能系统、公会系统、社交系统等核心功能模块。项目采用单体架构设计，使用 TCP Socket 进行网络通信，ProtoBuf 进行数据序列化，Entity Framework 进行数据持久化。

本项目的设计目标是提供一个稳定、高效、可扩展的游戏服务器框架，支持多人在线游戏体验，具备完善的玩家交互、战斗、社交等功能。服务器采用多线程架构，能够处理并发连接请求，并通过消息分发机制实现各功能模块的解耦。项目的客户端采用 Unity 引擎开发，通过 Protobuf 协议与服务器进行通信，实现了完整的前后端分离架构。

## 技术架构

### 网络通信层

游戏服务器采用 TCP Socket 通信方案，使用异步 IO 模型处理客户端连接。核心网络组件位于 `Network` 命名空间下，包括 `NetService`（网络服务管理）、`NetConnection`（连接管理）、`TcpSocketListener`（套接字监听器）等类。网络层采用事件驱动模式，通过 `NetEventArgs` 传递网络事件，使用 `INetSession` 和 `NetSession` 接口管理会话状态。所有网络消息通过 ProtoBuf 进行序列化，协议定义文件位于 `Lib/Protocol/message.cs`，支持高达 2392 行协议定义，能够满足复杂游戏逻辑的消息传递需求。

网络通信的核心流程如下：客户端通过 TCP 连接到服务器，服务器接受连接并创建 `NetConnection` 实例管理该连接。每个连接关联一个 `NetSession`，用于存储会话状态和响应数据。消息到达时，通过 `MessageDistributer` 分发到对应的处理函数，处理完成后将响应序列化并发送回客户端。服务器支持消息订阅机制，各个服务模块在初始化时注册消息处理器，实现了松耦合的设计。

### 数据持久层

数据访问层使用 Entity Framework 6.0 进行对象关系映射，通过 `DBService` 单例类管理数据库连接和操作。项目使用 SQL Server 数据库，连接字符串在 `App.config` 和 `GameServer.exe.config` 中配置，支持本地或远程数据库连接。数据库上下文 `ExtremeWorldEntities` 管理所有实体对象的增删改查操作，实体类包括 `TUser`（用户）、`TPlayer`（玩家）、`TCharacter`（角色）、`TGuild`（公会）等，实体关系通过 `Entities.edmx.diagram` 进行可视化设计。

数据管理层通过 `DataManager` 单例类实现，负责加载和缓存配置数据。数据文件位于 `Data/Tables` 目录下，包括技能数据、物品数据、地图数据等静态配置。`DataManager` 在服务器启动时加载所有配置数据到内存，提供高速的数据访问接口，减少运行时的数据库查询压力。这种设计将静态配置数据与动态业务数据分离，提高了系统整体性能。

### 核心业务层

游戏服务器的业务逻辑按功能模块划分到不同的 Manager 和 Service 类中。Manager 类主要负责游戏实体的管理，如 `CharacterManager`（角色管理）、`MapManager`（地图管理）、`GuildManager`（公会管理）等，负责实体的创建、销毁、状态更新等操作。Service 类主要处理客户端请求，如 `UserService`（用户服务）、`ChatService`（聊天服务）、`GuildService`（公会服务）等，负责接收请求、处理业务逻辑、返回响应。

服务器采用消息驱动架构，通过 `MessageDistributer<T>` 实现消息的分发和路由。每个 Service 在构造函数中订阅感兴趣的消息类型，当消息到达时自动调用对应的处理函数。这种设计使得各功能模块之间相互独立，便于代码维护和功能扩展。服务器主循环通过 `GameServer.Update()` 方法驱动，每 100 毫秒执行一次更新，处理地图管理器、竞技场管理器等需要周期性更新的游戏逻辑。

## 核心功能模块

### 用户系统

用户系统是游戏服务器的基础模块，负责玩家的账号管理和身份认证。`UserService` 实现了完整的用户注册、登录、角色创建和游戏进入流程。用户注册时，系统会创建 `TUser` 账号记录和关联的 `TPlayer` 玩家记录，每个玩家账号可以拥有多个角色。登录时，系统验证用户名和密码的正确性，并返回该账号下所有角色的列表供玩家选择。

角色创建功能允许玩家创建新角色，系统会自动初始化角色的各项属性，包括等级、位置、金币、生命值、法力值等。默认创建的角色等级为 1，初始位置在地图 1 的指定坐标，携带 100000 金币，1000 点生命值和 1000 点法力值。系统还会自动初始化角色的背包（20 格空间）、技能（根据职业配置）和初始物品（20 个红药和 20 个蓝药）。角色进入游戏时，`CharacterManager` 会创建运行时角色对象，`SessionManager` 会建立角色与网络连接的映射关系。

### 地图系统

地图系统负责管理游戏世界的空间划分和玩家位置追踪。`MapManager` 管理所有游戏地图的实例，每张地图由 `Map` 类表示，包含地图 ID、名称、怪物刷新点、NPC 位置等信息。当玩家进入游戏时，会根据角色上次保存的位置加载到对应地图。玩家在地图间移动时，系统会处理角色离开旧地图和进入新地图的逻辑，确保玩家能够正确感知周围环境和接收地图特定的事件。

地图还负责管理本地的聊天消息和玩家可见性。每个地图维护独立的本地聊天频道，玩家只能看到同一地图内其他玩家的聊天内容。地图还追踪区域内所有角色的状态，支持附近玩家列表查询和视野同步功能。`SpawnManager` 和 `Spawner` 负责管理怪物的定时刷新，每个地图可以配置多个刷新点，按照预设的时间间隔生成怪物，为玩家提供战斗和练级的对象。

### 战斗系统

战斗系统是游戏的核心玩法模块，提供了完整的战斗逻辑实现。`Battle` 类处理战斗的整个生命周期，包括战斗开始、技能释放、伤害计算、战斗结束等阶段。`Skill` 类实现了职业技能系统，支持多种技能类型（主动技能、被动技能）和效果（伤害、治疗、控制）。技能系统支持技能冷却、消耗（魔法值、体力值）、技能等级等机制，配置文件 `DataManager.Instance.Skills` 根据角色职业加载对应的技能列表。

`Buff` 和 `BuffManager` 实现了增益和减益状态系统，包括属性加成、持续伤害、属性削减等效果。`Bullet` 类处理投射物逻辑，支持远程攻击的飞行轨迹和命中判定。战斗系统还包含完整的属性计算逻辑，`Character` 类继承自 `Creature`，实现了生命值、法力值、攻击力、防御力、速度等属性的管理，支持属性的动态更新和状态异常处理。

### 公会系统

公会系统为玩家提供社交和组织功能，支持公会的创建、加入、管理和活动。`GuildService` 和 `GuildManager` 实现了完整的公会功能链。玩家可以消耗一定资源创建公会，自定义公会名称和公告。创建公会后，创建者自动成为公会会长（President），拥有任命副会长、踢除成员、转让会长等管理权限。

公会申请和加入流程采用双向确认机制：玩家提交申请，公会管理层收到通知后会决定是否批准。公会成员可以查看在线成员列表、参与公会聊天频道、接收公会公告。公会系统还实现了权限分级管理，不同职位的成员拥有不同的操作权限，如普通成员只能查看信息，副会长可以处理申请，会长可以进行任命和踢人等管理操作。公会数据持久化存储，支持公会成员列表、申请记录、历史公告等信息的管理。

### 聊天系统

聊天系统提供了多层次的即时通讯功能，支持世界频道、地图频道、队伍频道、公会频道和系统公告。`ChatManager` 采用分类存储的设计思路，每个频道独立管理聊天消息的历史记录。世界频道和系统频道维护全局消息列表，地图频道、队伍频道和公会频道则根据对应的 ID 索引消息列表，实现消息的定向分发。

聊天消息包含发送者 ID、名称、内容、时间戳等元数据，系统自动过滤和限制刷屏行为。每个频道保留最近的聊天记录（最多 100 条），并只显示最近 10 分钟内的消息，避免消息列表无限增长。`ChatService` 处理客户端的聊天请求，根据消息频道将消息分发到对应的管理器，支持消息的历史获取和新消息推送功能。

### 好友系统

好友系统支持玩家之间的社交关系管理，包括添加好友、删除好友、好友聊天等功能。`FriendManager` 维护好友关系数据，采用双向存储的设计：A 添加 B 为好友时，双方的好友列表都会增加对方记录。好友系统还支持好友分组（暂未实现）和在线状态查询，方便玩家了解好友的游戏状态。

好友关系创建时需要对方确认（可选设计），确认后双方成为好友，可以查看彼此的在线状态和基本信息。好友系统与聊天系统集成，好友频道的聊天消息通过 `ChatManager` 的队伍/公会机制处理。好友数据与角色数据关联存储，好友关系随角色删除或账号注销而自动解除。

### 组队系统

组队系统支持玩家组队进行副本挑战和团队活动。`TeamService` 和 `TeamManager` 实现了队伍创建、成员管理、队长转移、队伍解散等功能。玩家可以创建队伍并成为队长，也可以申请加入其他玩家的队伍。队伍支持最多 5 名成员（可配置），队长可以邀请其他玩家加入、任命新队长、踢除成员。

队伍频道提供独立的聊天空间，队伍成员可以进行实时沟通交流。队伍状态与副本系统关联，只有同一队伍的玩家才能进入特定的副本地图。队伍还支持装备掉落分配、经验分配等团队协作机制。队伍管理器维护所有活跃队伍的列表，支持按 ID 查找队伍和获取队伍成员信息。

### 任务系统

任务系统为玩家提供游戏目标和成长指引。`QuestManager` 管理任务进度和任务状态，支持主线任务、支线任务、日常任务等多种任务类型。任务数据在配置文件中定义，包括任务目标、完成条件、奖励内容等。玩家接取任务后，系统会追踪任务进度，当满足完成条件时自动触发任务完成逻辑并发放奖励。

任务系统支持任务链设计，多个相关任务按顺序串联，提供完整的剧情体验。任务追踪功能允许玩家查看当前接受的任务列表和进度。任务奖励包括经验值、金币、物品、道具等，奖励在任务完成时自动发放。任务状态持久化存储，玩家下线后再上线可以继续完成未完成的任务。

### 物品系统

物品系统管理游戏中的所有物品，包括装备、消耗品、材料、任务道具等。`ItemManager` 和 `ItemService` 实现了物品的获取、使用、丢弃、交易等功能。物品数据存储在 `TCharacterItem` 表中，与角色关联。每个物品实例包含物品 ID、堆叠数量、绑定状态等属性。

背包系统 `BagService` 管理角色的物品栏空间，默认提供 20 格背包容量。玩家可以通过扩展道具增加背包格数。物品使用逻辑根据物品类型区分：消耗品使用后增加角色属性（如红药回血、蓝药回蓝），装备使用后绑定到角色并提供属性加成。物品系统还支持物品的出售、分解等功能，为玩家提供物品管理的灵活性。

### 竞技场系统

竞技场系统提供玩家之间的对战玩法。`ArenaService` 和 `ArenaManager` 实现竞技场的匹配、对战、奖励机制。玩家可以进入竞技场与其他玩家进行 1v1 对战，竞技场采用积分匹配机制，根据玩家的竞技场分数匹配实力相当的对手。`Arena` 类记录竞技场比赛的详细信息，包括参战玩家、比赛结果、战斗时长等。

竞技场战斗采用独立的战斗模式，与普通战斗不同的是，竞技场战斗有固定的时间限制和胜负判定规则。战斗结束后，系统根据战斗结果发放竞技场积分奖励，积分影响玩家在竞技场排行榜上的排名。竞技场系统鼓励玩家参与对战，提供荣誉奖励和排名称号，激励玩家不断提升战斗技巧。

### AI 系统

AI 系统为怪物和 NPC 提供智能行为。`AIBase` 是所有 AI 行为的基类，定义了 AI 的生命周期和接口规范。`AIBoss` 实现了 Boss 怪的专属 AI 逻辑，包括特殊技能释放、血量阶段变化、召唤小怪等复杂行为。`AIMonsterPassive` 实现了被动怪的简单 AI，主要是在受到攻击时进行反击。

AI 系统的设计采用策略模式，可以方便地扩展新的 AI 行为类型。怪物 AI 与战斗系统集成，在战斗回合中调用 AI 决策选择行动。AI 行为包括移动到目标、释放技能、逃跑、呼叫支援等。AI 系统还支持状态机管理，怪物可以在巡逻、追击、战斗、逃跑等状态间切换，提供更真实的智能体验。

## 数据库设计

### 核心实体关系

数据库采用关系型设计，通过 Entity Framework 进行对象关系映射。核心实体包括：

- **TUser（用户表）**：存储玩家账号信息，包含用户名、密码、关联玩家（Player）等字段。每个 TUser 可以拥有多个 TCharacter（角色），但通常对应一个 TPlayer 记录作为玩家档案的顶层容器。

- **TPlayer（玩家表）**：代表一个完整的游戏存档，包含多个角色的集合。TPlayer 作为 TUser 和 TCharacter 之间的中间实体，支持一个账号拥有多个角色的设计模式。

- **TCharacter（角色表）**：存储角色的详细数据，包括名称、职业、等级、位置、生命值、法力值、金币、经验等。角色是玩家在游戏世界中的实体化身，关联物品、背包、技能、任务等扩展数据。

- **TGuild（公会表）**：存储公会的核心信息，包括公会名称、公告、会长 ID、创建时间等。公会成员存储在 TGuildMember 表中，公会申请存储在 TGuildApply 表中。

- **TCharacterBag（背包表）**：存储角色的背包数据，每个角色对应一个背包记录，包含背包格数和物品数据序列化字段。

- **TCharacterItem（物品表）**：存储角色拥有的物品实例，包括物品 ID、堆叠数量、绑定角色等信息。

- **TCharacterSkill（技能表）**：存储角色已学习的技能，包括技能 ID、等级等信息，关联技能配置表获取技能详情。

- **TCharacterQuest（任务表）**：存储角色的任务进度，包括任务 ID、当前进度、完成状态等信息。

- **TCharacterFriend（好友表）**：存储角色的好友关系，包括好友角色 ID、好友类型、添加时间等信息。

### 数据库配置

数据库连接字符串在配置文件中管理，支持灵活的数据库部署方式：

```xml
<connectionStrings>
  <add name="ExtremeWorldEntities" 
       connectionString="metadata=res://*/Entities.csdl|res://*/Entities.ssdl|res://*/Entities.msl;
       provider=System.Data.SqlClient;
       provider connection string=&quot;Data Source=.;Initial Catalog=ExtremeWorld;Integrated Security=True&quot;"
       providerName="System.Data.EntityClient" />
</connectionStrings>
```

默认配置使用本地 SQL Server 数据库，支持 Windows 身份验证连接。生产环境可以修改为数据库服务器地址、数据库名称和认证凭据。数据库迁移使用 Entity Framework 的 Code First 模式，通过实体类的变更自动更新数据库结构。

## 网络协议

### 协议定义

项目使用 Protocol Buffers（ProtoBuf）进行网络消息的序列化和反序列化，协议定义文件位于 `Lib/Protocol/message.cs`，包含超过 2392 行协议定义代码。ProtoBuf 提供了高效的数据压缩和快速的序列化性能，适合游戏服务器的高并发场景。

协议文件由 `.proto` 源文件编译生成，包含以下主要消息类型：

- **用户相关协议**：UserLoginRequest/Response（登录）、UserRegisterRequest/Response（注册）、UserCreateCharacterRequest/Response（创建角色）、UserGameEnterRequest/Response（进入游戏）、UserGameLeaveRequest/Response（离开游戏）

- **角色相关协议**：Character相关消息，包含角色属性、技能、装备等信息同步

- **公会相关协议**：GuildCreateRequest/Response（创建公会）、GuildListRequset（公会列表）、GuildJoinRequest/Response（加入公会）、GuildLeaveRequest（离开公会）、GuildAdminRequest（公会管理）

- **聊天相关协议**：ChatMessage（聊天消息）、ChatChannel（聊天频道枚举）

- **战斗相关协议**：SkillCastRequest（技能释放）、DamageInfo（伤害信息）、Buff更新消息

### 消息处理流程

网络消息的处理采用发布-订阅模式：

1. 客户端发送请求消息，服务器接收并通过 ProtoBuf 反序列化为请求对象
2. `MessageDistributer` 根据消息类型分发给对应的处理函数
3. 处理函数执行业务逻辑，构建响应消息
4. 响应消息通过 ProtoBuf 序列化，发送回客户端
5. 客户端接收响应消息，反序列化后更新游戏状态

这种设计实现了消息处理与业务逻辑的解耦，各个 Service 只需要关注自己的业务处理，不需要关心网络通信细节。消息分发器支持泛型参数 `T`，可以灵活处理不同类型的消息。

1. 使用 Unity 打开 `Src/Client` 目录

## 项目特点

### 架构设计

项目采用经典的三层架构设计，将表示层（客户端）、业务逻辑层（服务器服务模块）和数据访问层（EF 数据持久化）清晰分离。各功能模块通过 Manager 和 Service 模式组织，实现了高内聚、低耦合的设计目标。单例模式广泛应用于管理器和服务类，确保全局状态的一致性和访问的便捷性。

### 扩展性

项目架构支持多种扩展方式：

- **功能扩展**：通过添加新的 Service 和 Manager 类，可以方便地扩展游戏功能
- **协议扩展**：ProtoBuf 协议支持向后兼容的扩展，可以通过添加新字段扩展消息结构
- **存储扩展**：数据访问层抽象了数据库操作，可以方便地切换到其他数据库系统
- **网络扩展**：网络层采用接口设计，可以替换为其他网络框架或协议

### 性能考虑

项目在性能方面采取了以下措施：

- **配置缓存**：静态配置数据在启动时加载到内存，减少运行时数据库查询
- **连接管理**：使用连接池和会话管理，避免频繁创建销毁对象
- **消息分发**：事件驱动的消息处理模式，提高消息处理效率
- **批量操作**：Entity Framework 支持批量数据操作，减少数据库往返次数
